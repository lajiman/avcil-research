离线分析已有实验：不改训练代码，不重复训练

更新：三组受控评估及 CPU 一键运行见第 7 节。旧的单探针入口保持兼容。

1. 先看真实历史记录
在仓库根目录运行：
  python experiments_phase_8_rdcrosssdc_modular_gridsearch/analyze_loss_scales.py
运行后生成：results/loss_scale_analysis/report.html（相对于本说明所在目录）。
24 次 hinge 实验，48,000 条 epoch 记录，其中 43,200 条为增量训练。
可恢复 total、CMR、CrossSDC-I/C 及其加权值；其余项只能得到合计。
这些是训练时逐 batch 标量的 epoch 平均，不是 checkpoint 上的重算。
本批 CrossSDC-C 系数为零，原始数值不等于优化贡献。

2. 在原训练服务器环境运行 checkpoint 探针
需要：PyTorch、numpy、h5py、tqdm；请使用已有训练环境和输入特征。
只加载自己项目产生的可信 full-model pickle checkpoints。
在仓库根目录，用真实服务器路径替换下面的占位路径：

  python experiments_phase_8_rdcrosssdc_modular_gridsearch/probe_checkpoint_losses.py --run-dir /path/to/one_experiment --feature-root /path/to/VGGSound --meta-root /path/to/balance --output /path/to/offline_analysis/one_experiment --steps 1 5 9 --batches 3 --lambdas 0 .01 .03 .1 .3 1 --device cuda

run-dir 必须直接包含 step_0_best_model.pkl ... step_9_best_model.pkl。
feature-root 需有 visual_features.h5 和 audio_pretrained_feature/audio_pretrained_feature_dict.npy。
meta-root 需有 all_id_category_dict.npy、category_encode_dict.npy、all_classId_vid_dict.npy。
输出目录必须新建或为空，不能位于 checkpoint 目录内。
默认一次只测一个实验的 3 个阶段、每阶段 3 个 batch；先用一个 seed 跑通。
不调用训练入口，不构造 optimizer，不执行 optimizer.step，不写回 checkpoint。
验证完成后再增加 --batches；没有必要一开始扫描 240 个 checkpoint。

3. 口径与公平比较
读取学生 checkpoint 中的原参数；前一阶段最佳 checkpoint 是该运行自己的教师。
学生/教师均为 eval 模式；仍开启学生 autograd。原有此模型无 dropout/BN，
但以后若加入此类层，eval 探针仍须与 train 模式历史记录区分。
沿用原 CE、KD(T=2)、模态对比、CrossSDC、CMR、注意力 KL 公式和 reduction。
默认当前/回放 batch size 沿用原训练参数，通常各 128。
对比损失依赖同 batch 的其他样本，不能把改小 batch 或微批累加视为等价。
prototype bank 的无梯度构建 batch 为最多 32，不改变其全 memory 统计定义。

没有原 replay IDs 时，会从 train split 选固定、按类平衡的新 probe memory，
在这份 memory 上重建教师原型和 Trust 权重，且所有 replay probe 都属于 memory，
从而保持 leave-one-out 的内部一致性。这是新的受控测量，不冒充原回放 memory。
probe_manifest.json 保存全部 memory IDs 和每个 batch 的 current/replay IDs。
比较其他实验时，加 --probe-manifest /path/to/first/probe_manifest.json，使用相同样本。
不同实验仍各自使用自己的教师；因此这是各自训练目标的测量，不是共享教师实验。
若有原 memory IDs，可加 --replay-ids /path/to/replay_ids.json，格式如：
  {"1":["video_id_1","video_id_2"],"5":[...],"9":[...]}
每个阶段列表必须覆盖全部旧类，列表中的实际 ID 需完整，不能使用这里的占位例子。
不能同时使用 --probe-manifest 与 --replay-ids。

4. 输出
components.csv：逐 batch 的全部原始/加权 loss、原始/加权梯度范数、
相对全部非 CMR 加权项之和的范数比、余弦。
component_summary.csv：上述量的 batch 均值与 batch 标准差。
gradient_pairs.csv：两两 loss 梯度余弦，可定位与 CE/KD/对比项的冲突。
lambda_sweep.csv：固定同一 checkpoint、batch、教师、原型与权重，仅改全局 lambda。
包含 CMR/base 范数比、总梯度范数、总梯度与 base 的余弦、等范数 lambda。
parameter_scope 分 all、feature_and_attention、classifier；CMR 通常不直接作用于 classifier。
metadata.json：运行参数、checkpoint/代码哈希、参数及 buffer 未改变检查。
只有 metadata.json status=complete 才代表全部测量完成；中断时可留下部分 CSV。

5. 解释
令 b=grad(sum of weighted non-CMR losses)，c=grad(raw CMR)。
总梯度为 b+lambda*c；范数不能直接相加，需要梯度内积/夹角。
rho=lambda*||c||/||b||，是该批该参数范围内的瞬时相对尺度。
cos(c,b)<0 表示一阶目标存在冲突，>0 表示部分同向，0 表示正交。
lambda_equal=||b||/||c|| 仅是等梯度范数参考，绝不是自动最优 lambda。
同 checkpoint 扫 lambda 的线性缩放是数学事实；改变 lambda 后实际训练出的
checkpoint、教师和激活样本也会变，需比较已有实验，而不能用瞬时扫参替代。
模型只存每阶段最佳状态，不能重建未保存 epoch 的完整梯度历史。
参数梯度不是 Adam 实际更新；本测量不包括 Adam 状态、weight decay 或学习率。
归一化后的各项梯度范数比例不是可相加的百分比。

6. 验证
  python -m unittest discover -s experiments_phase_8_rdcrosssdc_modular_gridsearch/tests -p test_offline_loss_probe.py -v
纯 Python 测试覆盖冲突/正交/零梯度几何、可复现采样及 LOO membership。
PyTorch 测试还核对真实模型的离线计算与训练代码中的实际 batch 公式/梯度，
覆盖 hinge/direct/exp/log1p、自适应与均匀权重，以及可选损失关闭情形。
本机缺失运行依赖时这些运行时测试会明确标为 skipped，不能当作已通过。
先在原训练环境完成这两项运行时测试，再执行真实实验的探针。

7. 三组受控评估（推荐用于这次分析）

新增入口：probe_checkpoint_three_way.py。
同一个 checkpoint 依次完成下面三组，并在所有 CSV 中写 experiment_group：

  original_memory
    原 replay memory 上抽取查询，用原 memory 构建原型，使用历史 CSV 的原权重。
    衡量最佳 checkpoint 对训练回放约束的满足程度与剩余梯度。

  heldout_fixed_reference
    查询来自原 memory 之外的旧类 train 样本；保持上一组原型、权重完全不变。
    查询不属于原型库，因此不从正类原型中减去该查询的 teacher 特征。
    这里 heldout 仅表示未进入该阶段 memory，不是 val/test 或从未训练过的数据。

  fresh_memory
    与第二组使用完全相同的查询，但改用一份新的 memory 重建原型和 Trust/权重。
    查询属于新 memory，因此恢复 leave-one-out。
    衡量换一套 memory/参考体系之后的损失与梯度；第二、三组仍共同改变了原型与权重，
    不把两者各自的影响单独归因。

采样控制：
  新 memory 与原 memory 严格不相交，每类样本数相同。
  每个 batch 三组使用完全相同的 current IDs 和完全相同的旧类标签序列。
  第二、三组的旧类 query IDs 也完全相同；batch 内不重复，batch 之间可重复。
  每个 step 只有一份新 memory。batch 标准差不能表示更换 memory 或 seed 的不确定性。
  因为增加了“不相交、类别匹配”控制，新 memory 不会复用旧版探针的采样清单。
  类别样本不足时明确报错，不会偷偷缩小 batch、改变类比例或使用重复样本。

原 memory 如何恢复：
  默认按 checkpoint 的训练 seed、本地元数据的原始顺序、feature 可用性，
  从 step1 顺序重放 Python random.sample 及旧类列表前缀截断；不执行训练。
  这仅产生候选历史 IDs。构建 teacher 原型后，逐类核对历史 prototype_count、
  两个方向的 Reliability、Trust 和权重（atol=2e-5, rtol=2e-4；count 必须完全一致）。
  任一项失败就停止，保存 reference_checks.csv，不降级为新 memory 冒充原 memory。
  校验是历史统计指纹的一致性证据，并非原始 ID 日志的替代品。
  如果拥有原始 ID 日志，可用 --replay-ids JSON；仍执行上述数值校验。
  --probe-seed 只控制评估查询/新 memory，原 memory 使用 checkpoint 的训练 seed。
  当前入口要求 adaptive_crosssdc_cmr、Trust-only 权重及完整历史指标。
  原型构建按原公式计算；第一、二组最终直接使用 CSV 记录的权重，不使用其重算近似值。
  best epoch 按验证准确率的第一次最大值选取，与训练保存策略一致。

单个设置的 CPU 命令（仓库根目录）：
  python experiments_phase_8_rdcrosssdc_modular_gridsearch/probe_checkpoint_three_way.py --run-dir /path/to/experiment --feature-root /path/to/VGGSound --meta-root data2/balance --steps 1 5 9 --batches 3 --device cpu --threads 4 --output experiments_phase_8_rdcrosssdc_modular_gridsearch/results/three_way_one_run

默认寻找 run-dir 同级的 metrics/<实验目录名>/rd_crosssdc。
如果历史指标放在其他位置，补 --metrics-dir /path/to/metrics/<实验名>/rd_crosssdc。
省略 --output 时自动写入本文件所在目录的 results/three_way_<时间>_<实验名>。
省略 --lambdas 时只测该 checkpoint 保存的实际 lambda，不会默认扫描其他系数。
指定 --lambdas 则额外生成该模型、该 batch 下的局部缩放比较，仍包含实际训练 lambda。

一次运行先前两个 hinge 设置（tol=.01，seed42，lambda=.03/alpha=.5 与 lambda=.1/alpha=1）：
  python experiments_phase_8_rdcrosssdc_modular_gridsearch/run_three_way_hinge_cpu.py --feature-root /path/to/VGGSound --threads 4

这条命令不需要 Slurm；两个设置顺序执行，默认 steps=1,5,9，每组各 3 batch。
自动使用仓库 data2/balance 与 save_commands_cmr_hinge_tolerance_focus_3seeds；
可通过 --meta-root 和 --archive-root 指向服务器上的实际位置。
第二个设置复用第一个设置的三组采样清单；它自己的原 memory 仍需独立重建并通过校验。
输出：results/three_way_hinge_cpu_<时间>/
        batch_metadata.json
        lambda_0p03_alpha_0p5.log
        lambda_0p1_alpha_1p0.log
        lambda_0p03_alpha_0p5/<下面列出的 CSV/JSON>
        lambda_0p1_alpha_1p0/<下面列出的 CSV/JSON>

CPU 开销控制：
  默认做三组完整梯度评估，主要梯度计算次数约为之前单探针的 3 倍。
  可先加 --steps 9 --batches 1 检查一阶段；正式测量须选择另一个新输出目录。
  --loss-only 只前向计算 loss/margin/违反比例，不计算梯度，梯度列留空而不是填 0。
  --dry-run（仅 CPU 两设置入口）只检查 checkpoint 路径并打印命令。
  不能通过缩小 batch 后直接与原训练 batch 的对比损失混为同一口径。

每个设置的输出：
  component_summary.csv：按 experiment_group/step/parameter_scope/component 汇总尺度。
  components.csv、gradient_pairs.csv、lambda_sweep.csv：保留原探针逐 batch 梯度输出格式，
    增加 experiment_group；loss-only 不产生后两个文件。
  cmr_batches.csv：CMR 原始/加权 loss、两个方向的违反比例、平均违反幅度、
    仅活跃样本的平均违反幅度，以及旧定义的 mean_deficit。
  cmr_samples.csv：实际 query ID、类别、是否属于参考 memory、teacher/student margin、
    有符号 margin 差、deficit、超过 tolerance 的 violation、实际 penalty、类别权重，
    及该样本对 batch CMR 的原始/加权贡献（贡献在 batch 内相加可恢复 CMR）。
    非 hinge 情形中 violation>0 不等于该 penalty 的梯度非零。
  class_reference.csv：原、新参考体系的每类 count、Reliability、Trust 和使用的权重。
  reference_checks.csv：原 memory 重建的逐类校验值、误差、容差和通过标记。
  historical_comparison.csv：三组 checkpoint 测量与原 best epoch 均值/违反比例并列。
    原 epoch 均值在模型不断更新时测得，不要求它等于保存后 checkpoint 的重算值。
  coverage.csv：查询覆盖数、参考 memory 大小及与原 memory 的重合数量。
  probe_manifest.json、original_replay_ids.json：三组可重放的完整采样清单与候选历史 IDs。
  metadata.json：complete/failed/running 状态、历史 CSV/代码/checkpoint 哈希、
    参考校验和参数/buffer 未修改检查；只有 complete 才能作为完整测量结果使用。

这些输出仍是最佳 checkpoint 上的局部测量，不会恢复未保存 epoch 的梯度，
也不是 Adam 实际更新比例。三组用于分开检查原约束满足、memory 外样本保持、
换参考体系后的敏感性；不从单个 seed 或单份新 memory 推断总体最优 lambda。
